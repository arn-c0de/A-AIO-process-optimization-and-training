### Fixed (code review 2026-11-08: training comparability)
- `training.fit_epoch` validates with plain cross-entropy (`plain_criterion`) even when `train.label_smoothing` is set; the smoothed criterion had been used for `val_loss` too, so val-loss curves of runs with and without smoothing were not comparable (the docstring already promised the fix).
- `train --resume`: `train.lr` and `train.weight_decay` of the dataset config now win over the values restored from the checkpoint's optimizer state (they also become the base lr of the cosine schedule). Before, a changed config lr was silently ignored and a resume without scheduler kept the already decayed lr.
- `train --out-mode last` no longer rewrites `best_val_f1` / `best_epoch` every epoch; the best bookkeeping is independent of what `--out` receives. A resume into a new `--out` path also no longer replaces the resumed best with a worse first epoch.
- `eval` on a multi-model bundle writes `report_<bundle>_<profile>.json` (`evaluation.report_path_for(..., profile_id=)`); evaluations of one bundle on datasets of different profiles used to overwrite each other's `report_<bundle>.json`. Arena and `batch-predict` history match reports by content (`model_path` / `model_stem`), so they pick the new files up unchanged.
- `train-profile` uses `train.scheduler` / `train.warmup_epochs` like `train` and accepts `--threads` (`training.set_torch_threads`).
- `models.build_resnet18(pretrained=True)` raises `RuntimeError` when the ImageNet weights cannot be loaded instead of silently training from random init under a config that says `pretrained: true` (hint: `train.pretrained: false`).
- `batch-predict` accepts datasets in which a model class has no samples (support 0, warning); only labels the model was not trained on are an error. The error text still contains "do not match dataset classes" for the Weights tab.
- Epoch and inference losses are sample-weighted means (`train_epoch`, `eval_utils.run_inference`); the last, smaller batch used to count like a full one.
- `splits.stratified_splits` raises `ValueError` naming the sample instead of a bare `KeyError` for a meta row without label; `eval_utils.eval_loader` casts `eval.num_workers` to int; `gui.core.tasks.TaskHandle.progress` does its coalescing test-and-set under the lock.
- `model_bundle.safe_profile_filename` is public (the private name stays as alias). Tests: `tests/test_training_options.py` (val loss under smoothing, sample-weighted losses, resume lr / best bookkeeping, pretrained failure).

### Changed (code review 2026-11-08: modernisation)
- `requires-python >= 3.11` (README said 3.11+ already; QUICKSTART updated).
- `[tool.ruff]` in `pyproject.toml` (`F`, `E9`, `B`, `UP`, `PLE`, `PLW1510`; target py311). The mechanical findings are fixed: deprecated `typing` imports, quoted annotations, `datetime.timezone.utc` -> `datetime.UTC`, `typing.Union`, unused imports / loop variables, explicit `check=False` on every `subprocess.run`. `simple_sim.board.__all__` lists the whole eagerly imported surface.
- `models.load_checkpoint` (and the bundle index scan) load with `weights_only=True` first and fall back to full unpickling only for legacy files; Simple-Sim checkpoints contain tensors and plain containers only.
- `train` / `train-profile`: the training DataLoader shuffles from its own `torch.Generator` seeded with the train seed, so the sample order no longer depends on how much global RNG the model init and augmentation consumed. Shuffle order of existing runs is therefore not reproduced bit for bit.

### Changed (training speed on CPU)
Models, images, checkpoints and the config defaults are unchanged; tests `tests/test_data_loader.py`, additions in `tests/test_training_options.py`.
- **Per-image transforms run single-threaded** (`data_loader.single_threaded_torch` / `apply_transform`, used by the datasets and by `preprocess_bgr`, i.e. train, eval, predict, sample-check and the real-crop tools). With `num_workers: 0` (the config default) the transforms ran in the main process on torch's whole thread pool, and for one 256 px image the fork/join of 16 threads dominates: on the i9-12900K `ToTensor` + `Normalize` took 27 ms instead of 0.3 ms per image, `ColorJitter` 600 ms instead of 10 ms. Loading one train sample now takes 4 ms instead of 97 ms (16 ms instead of 604 ms with `train.augment`); the tensors are bit-identical. DataLoader workers were already single-threaded, so `num_workers > 0` runs are unaffected.
- New `train.cache_images: true`: decoded images are kept in RAM after the first epoch (about 200 KB per 256 px image; each DataLoader worker holds its own copy), which removes the PNG decode (1-2 ms per image) from every further epoch.
- New `train.freeze: [stem, layer1, ...]`: ResNet stages that keep their (pretrained) weights (`models.freeze_stages`, `trainable_parameters`). The optimizer only sees the remaining parameters, backward stops at the first trainable stage and the frozen BatchNorm layers stay in eval mode. This changes what is trained, so it is off by default; with small synthetic sets freezing `stem` + `layer1` is a common choice.
- New `train --threads N` (`train_model(threads=)`): torch intra-op threads for CPU training, printed in the run header. On the hybrid i9-12900K (8 performance + 8 efficiency cores) a single-batch benchmark favoured 8 threads over torch's default of 16 by about 2x, but whole epochs on a heavily loaded machine showed no reliable difference; measure on an idle machine before changing it. bf16 autocast on this CPU (no AVX-512 BF16 / AMX) is six times slower than fp32 and `channels_last` gives no gain, neither was adopted.
- `docs/guides/CHEATSHEET.md` "Performance Tips" describe these options instead of editing `scripts/train.py`.

### Added (training quality; every option defaults to the old behaviour, `configs/run_0001_xdomain.yaml` turns them all on)
- `defects.placement_sampling: legacy | continuous` (run config, default `legacy`, bit-identical): the legacy sampler never renders anything between 0.7 x tolerance (last OK) and tolerance + 1 px (first MISALIGNED), i.e. exactly the band the classifier has to learn. `continuous` fills the tolerance up to the boundary for OK, starts MISALIGNED right behind it with half the samples in the first quarter of the range (tail to the legacy maximum) and draws the shift direction uniformly. - Blender backend rebuilt around the 2D look: the photoreal board (mask, traces, vias, silkscreen, pad finish) is baked per job and used as texture, Blender gets the 2D pad layout (no own pad logic, QFN/SOT special cases removed), solder fillets are height-field meshes, parts get end caps, gull-wing leads, pin-1 marks and markings, tombstones pivot about their anchored end, lighting is a calibrated AOI ring light, the camera is orthographic top-down framed to the ROI with sRGB output, and the 2D camera model is applied to every render. 3D profiles now share the 2D geometry semantics (SOT-23/QFN ranges from the 2D profiles, SOIC-16 at real scale), drop the unused substrate/copper materials and key/fill lights, and use a top-down camera. Because geometry semantics and look changed, the 3D profiles are now `*_3d@2`; datasets of the `@1` profiles cannot be extended (profile hash check) and should be regenerated.
- Default image filters no longer enable motion blur (11 px on every image) and the random dark shadow blob; neither occurs on a static AOI camera. Both stay available in the filter settings.
- `photoreal` 2D: silkscreen is placed around the nominal footprint instead of the shifted body (removes a label leak for MISALIGNED).
- Tombstones rendered as standing parts in both backends: from above the steep top face (length*cos(tilt), starting behind the anchor) and the upright end face (height*sin(tilt)) are visible; on chips that end face is the bright tin end cap, shaded as metal. 2D shadow is the projection of the standing part along the light. Blender: satin end caps and a diffuse top light next to the ring light, so flat metal (solder tops, upright end caps) is bright as on AOI images; board colours recalibrated.
- Tombstone tilt is sampled from `tolerances.tombstone_tilt_deg` up to fully upright (90 deg) instead of only 10 deg above the threshold; both renderers handle any tilt. `chip_0603_resistor_3d@2` uses a 30 deg threshold (partly lifted ends count as tombstones). Blender end caps no longer share the body's end face (upright caps rendered black).
- New default profile `chip_0603_resistor@2`: TOMBSTONE from 30 deg tilt (partly lifted ends) instead of 75 deg; run configs and GUI default to it (`simple_sim.config.DEFAULT_COMPONENT_PROFILE`). `chip_0603_resistor@1` stays for existing datasets and models.
- Camera model configurable via `render.camera` (lens blur, read/shot noise; 2D and 3D) and new `tools/calibrate_camera.py`, which fits these values to real camera ROIs (self-tested: recovers a known blur/noise setting). Solder-mask palette extended with the brighter greens of the production boards.
- `photoreal` calibrated on photos of the production boards: measured teal-green mask palette and copper-under-mask ratio (replacing estimates), copper pours, more and mostly tented vias, neighbour chip parts around the inspected part (2D and baked into the 3D board), silkscreen only in 55 % of samples.
- Residue as a label-neutral nuisance (`render.rework_artifacts`, default 0.3): flux residue, smeared yellow contamination and patch wires as seen on the production boards, never inside the inspected part's area (tested).
- New defect classes `SOLDER_BALL` and `EXCESS_SOLDER` (2D photoreal and flat, 3D): one layout function decides ball positions and affected pads for both backends. Added to the default run configs (`run_0001`, `run_0500`, all `*_3d`) and to the unreleased `@2` profiles; released `@1` profiles are unchanged.
- Phone photos: `render.camera.preset: phone` (oblique 5-40 deg, zoomed out up to 2.5x with proportionally more neighbour parts, softer with depth-of-field falloff, more noise, ISP sharpening, JPEG); all values overridable (`tilt_deg`, `zoom`, `defocus`, `sharpen`, `jpeg_quality`, ...) and validated. 2D projects a larger board area, Blender tilts its camera. New `configs/run_0001_phone.yaml`. Parts are drawn in local windows (worst-case phone image 98 s -> 1.5 s).
- New `tools/sim_to_real.py`: measures the gap between synthetic and real ROI folders (1-NN two-sample accuracy and NN distance ratio on ResNet18 embeddings).
- QFN footprints now render real pad rows (`qfn_<N>` -> N/4 pads per side) plus the exposed thermal pad.
- Code review fixes across core, scripts, tools and GUI (sharpen filter saturation, rotation-strength scaling of cardinal orientations, ensemble checkpoints in `eval.py`, bundle report location, merged-dataset validation, v2 manifest extend history, Blender light target, GUI settings/dataset-selection bugs, split-file creation on move, and removal of dead or duplicated code).
